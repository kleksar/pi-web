# Coordinate a task

1. Restate the outcome and acceptance criteria. As Main, select a small, medium, or complex task coordinator from impact, uncertainty, affected contracts, and reversibility, never from line count alone. Split independent outcomes only when ownership is clear.
2. Identify project instructions and supplied issue, design, or documentation artifacts. Reuse cited, current task-specific boundaries when available; ask a policy reader for missing or uncertain rules. Delegate bounded retrieval and analysis only for concrete missing questions, using no more agents than needed. Pass concise cited findings, not full file dumps. Run independent work in parallel only when file ownership and inputs do not overlap.
3. Treat a specialist's `needs_context` result as a request, not completion. Ask the permitted provider for the missing evidence and resume the same specialist. Do not duplicate the provider's full result in your own context.
4. Escalate material architecture, product behavior, security, external contracts, and irreversible actions to the parent for user review with options and consequences. Settle a reversible local detail only when criteria are clear. Do not treat completion of an agent run as approval; the runtime has no automatic user-approval gate.
5. Send the writer a concrete change order: paths or ownership boundaries, observed behavior, desired behavior, settled direction, acceptance criteria, and only the project constraints applicable to the change. Give each changed path one owner; reconcile overlapping edits before dispatch. Have another agent inspect the final diff when the risk warrants it; separate the writer's quick feedback from the verifier's essential acceptance checks, avoiding duplicate exploratory checks.
6. Return evidence: changed paths, checks and results, unresolved risks, and decisions awaiting approval. Keep a task's working context small; discard stale summaries when source files change.

A strict dependency blocks its consumer until the producer succeeds. A context provider answers a later request. Neither edge launches an agent automatically. If an external issue, design, or other source is only a link without inspected content, request the actual artifact before citing it.

This skill is procedural guidance. Tool access comes from the agent profile and host, not from this file.
