# Interface text

Pi Web currently supports **English only**. UI strings live in
`lib/i18n/messages/en.ts`, and client components read them through `useI18n`.
There is no language selector. The UI always uses `en`, regardless of the
browser language. When upgrading from an older release, the `I18nProvider`
removes the obsolete `pi-locale` preference from local storage; push
subscriptions registered with an older locale still receive English messages.

## Using UI messages

```tsx
import { useI18n } from "@/hooks/useI18n";

export function ExampleButton() {
  const { t } = useI18n();
  return <button aria-label={t("example.open")}>{t("example.open")}</button>;
}
```

Components must render inside `I18nProvider`, which is already mounted in
`app/page.tsx`. Use interpolation for runtime values:

```tsx
<span>{t("session.messageCount", { count: messageCount })}</span>
```

Messages use stable keys and `{count}` placeholders. Add new keys to
`lib/i18n/messages/en.ts`; the demo's corresponding package is
`demo/lib/i18n/messages/en.ts`. Keep product names, paths, tool output,
model and provider names, and server errors unchanged. Missing keys warn in
development and display the key, so check the UI after adding messages.

The registry and formatter remain in place so more languages can be added in
the future. Supporting another language would also require an explicit
product decision to restore locale selection, persistence, and notification
translations.
