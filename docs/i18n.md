# English UI Text

Pi Web currently ships an English-only interface. The existing `useI18n` hook,
`I18nProvider`, and message keys remain in place so components can share UI
text and format values consistently. The English messages are defined in
`lib/i18n/messages/en.ts`. There is no language selector or browser-language
detection.

## Using UI Text in a Component

Client components get the translation function from `useI18n`:

```tsx
import { useI18n } from "@/hooks/useI18n";

export function ExampleButton() {
  const { t } = useI18n();

  return <button aria-label={t("example.open")}>{t("example.open")}</button>;
}
```

The component must be rendered below `I18nProvider`, which the application
root already provides in `app/page.tsx`.

Use parameters for values that change at runtime rather than concatenating
pieces of text:

```tsx
<span>{t("session.messageCount", { count: messageCount })}</span>
```

The corresponding message in `en.ts` can use `{count}`:

```ts
"session.messageCount": "{count} messages"
```

## Adding or Changing UI Text

1. Add a stable, descriptive key to `lib/i18n/messages/en.ts`. Group keys by
   feature, such as `chat.*`, `files.*`, `settings.*`, or `common.*`.
2. Use `t("namespace.key")` for visible text, `title`, `aria-label`, and
   `placeholder` values.
3. Use interpolation for counts, names, paths, and other runtime values.
4. Leave product names, model names, provider names, commands, file paths,
   user content, tool output, and server-provided error details unchanged.
5. Do not match an API error against its English text. Use keys for the local
   UI fallback around it.

If a key is missing, the formatter returns the key itself and emits a
development warning. Keep the English message set complete.
